# Deploying Mallow

> ## Read this first
>
> This runbook creates billable Google Cloud resources and publishes a public
> service. Follow it only if you intend to run your own instance; every command
> is written to be pasted in order, and the order is the point.

## Deployment shape

| Component | Configuration |
|---|---|
| Application | One Cloud Run service in `asia-northeast1` |
| Model | `gemini-3.7-flash` on Google Cloud through `google-genai` |
| Model location | `global`, deliberately separate from the Cloud Run region |
| Identity | Firebase Authentication: Google and Anonymous providers |
| Records | Firestore Native mode, `users/{uid}/…` |
| Autonomous work | Cloud Scheduler → authenticated task endpoint |
| Export | PDF, CSV and JSON, generated by the service on request |

The browser never talks directly to Firestore. The Python server SDK bypasses
Firestore Security Rules and uses IAM, so per-user isolation is enforced by the
server's verified uid and workspace path. Client Rules are deny-all.

Cloud Run eventually allows public invocation because browsers need to reach
the application. Public invocation is not access to records: private routes
still require a verified Firebase identity, and no request may name another uid.

## Before starting

In Firebase Console:

1. Add Firebase to the existing Google Cloud project.
2. Register a Web app.
3. Authentication → Sign-in method: enable **Google** and **Anonymous**.
4. Copy the Web app's `apiKey` and `authDomain`.

Keep one terminal open for the complete sequence below.

```bash
export PROJECT_ID="YOUR_PROJECT_ID"
export REGION="asia-northeast1"
export SERVICE="mallow"
export RUNTIME_SA="mallow-run@${PROJECT_ID}.iam.gserviceaccount.com"
export TASKS_SA="mallow-tasks@${PROJECT_ID}.iam.gserviceaccount.com"
export FIREBASE_API_KEY="PASTE_THE_WEB_APP_API_KEY"
export FIREBASE_AUTH_DOMAIN="PASTE_THE_WEB_APP_AUTH_DOMAIN"
export SESSION_SECRET="$(openssl rand -hex 32)"

gcloud auth login
gcloud config set project "$PROJECT_ID"
gcloud services enable \
  run.googleapis.com \
  aiplatform.googleapis.com \
  artifactregistry.googleapis.com \
  cloudbuild.googleapis.com \
  identitytoolkit.googleapis.com \
  firestore.googleapis.com \
  cloudscheduler.googleapis.com
```

## Stage 1 — create Firestore and publish deny-all client Rules

Enabling the API does not create a database. Mallow's server client uses the
`(default)` database, so create it explicitly if it is absent.

```bash
if ! gcloud firestore databases describe --database='(default)' >/dev/null 2>&1; then
  gcloud firestore databases create \
    --database='(default)' \
    --location="$REGION" \
    --type=firestore-native
fi

# One-time interactive Firebase CLI login on this machine.
npx --yes firebase-tools login
npx --yes firebase-tools deploy \
  --only firestore:rules \
  --project "$PROJECT_ID"
```

`firebase.json` points to `deploy/firestore.rules`. That rule denies every Web,
iOS and Android SDK request. The server SDK bypasses Rules and is controlled by
IAM, so the rule is not described as a second server-side isolation layer. Its
enforced client rule is exactly `allow read, write: if false;`.

## Stage 2 — create the runtime and Scheduler identities

```bash
gcloud iam service-accounts create mallow-run \
  --display-name "Mallow (Cloud Run)"
gcloud iam service-accounts create mallow-tasks \
  --display-name "Mallow (scheduler)"

gcloud projects add-iam-policy-binding "$PROJECT_ID" \
  --member "serviceAccount:${RUNTIME_SA}" \
  --role "roles/aiplatform.user"
gcloud projects add-iam-policy-binding "$PROJECT_ID" \
  --member "serviceAccount:${RUNTIME_SA}" \
  --role "roles/datastore.user"
```

`roles/datastore.user` is the document read/write role. Do not grant
`datastore.owner`. The runtime account has no mail, bucket or database-admin
permission.

## Stage 3 — deploy privately and obtain the real service URL

Do not configure the Scheduler yet. Its OIDC audience must be the URL produced
by this deployment.

```bash
gcloud run deploy "$SERVICE" \
  --source . \
  --region "$REGION" \
  --service-account "$RUNTIME_SA" \
  --set-env-vars "GOOGLE_CLOUD_PROJECT=${PROJECT_ID},GEMINI_LOCATION=global,MALLOW_DATA_DIR=/tmp/mallow,MALLOW_FIRESTORE=1,MALLOW_SESSION_SECRET=${SESSION_SECRET},FIREBASE_PROJECT_ID=${PROJECT_ID},FIREBASE_API_KEY=${FIREBASE_API_KEY},FIREBASE_AUTH_DOMAIN=${FIREBASE_AUTH_DOMAIN},REQUIRE_FIREBASE_AUTH=1" \
  --memory 512Mi \
  --cpu 1 \
  --max-instances 3 \
  --timeout 120 \
  --no-allow-unauthenticated

export URL="$(gcloud run services describe "$SERVICE" \
  --region "$REGION" \
  --format='value(status.url)')"
echo "$URL"
```

Now add the hostname from `$URL` (without `https://`) in Firebase Console →
Authentication → Settings → Authorized domains. Google sign-in will otherwise
refuse the Cloud Run domain.

Do not attempt the application-level curl checks yet. While the service is
private, Cloud Run IAM answers before Flask, so those responses cannot prove
the application's 401/403 behavior.

## Stage 4 — attach the Scheduler

The Cloud Run service exists now, so its IAM binding can finally be created:

```bash
gcloud run services add-iam-policy-binding "$SERVICE" \
  --region "$REGION" \
  --member "serviceAccount:${TASKS_SA}" \
  --role "roles/run.invoker"

gcloud run services update "$SERVICE" \
  --region "$REGION" \
  --update-env-vars "TASKS_SERVICE_ACCOUNT=${TASKS_SA},TASKS_AUDIENCE=${URL}"

gcloud scheduler jobs create http mallow-reflections \
  --location "$REGION" \
  --schedule "* * * * *" \
  --time-zone "Asia/Tokyo" \
  --uri "${URL}/tasks/reflections" \
  --http-method POST \
  --oidc-service-account-email "$TASKS_SA" \
  --oidc-token-audience "$URL"
```

`TASKS_SERVICE_ACCOUNT` and `TASKS_AUDIENCE` are set in one revision. The app
refuses to start if the account exists without its audience. Setting the
service account also disables the local task-key path.

## Stage 5 — allow browsers to reach the app, then verify

🔴 `--allow-unauthenticated` is a flag on `gcloud run deploy`, not on
`gcloud run services update`; passing it here fails with `unrecognized
arguments`. Opening an existing service means adding the IAM binding that the
flag would have added. Verified against a live service on 2026-08-23.

```bash
gcloud run services add-iam-policy-binding "$SERVICE" \
  --region "$REGION" \
  --member=allUsers \
  --role=roles/run.invoker

curl -s "$URL/health"
curl -s -o /dev/null -w 'garden, signed out → %{http_code}\n' \
  "$URL/garden"                                                   # expect 401
curl -s -o /dev/null -w 'task, no token → %{http_code}\n' \
  -X POST "$URL/tasks/reflections"                               # expect 403
curl -s -o /dev/null -w 'task, forged token → %{http_code}\n' \
  -H "Authorization: Bearer not-a-real-token" \
  -X POST "$URL/tasks/reflections"                               # expect 403
curl -s -o /dev/null -w 'garbage Firebase token → %{http_code}\n' \
  -H "Authorization: Bearer not.a.jwt" \
  "$URL/whoami"                                                   # expect 401

gcloud scheduler jobs run mallow-reflections --location "$REGION"
```

🔴 **Do not verify with `/healthz` on Cloud Run.** Google's frontend answers
that exact path with its own 404 page before the request reaches the
container: on 2026-08-23 the deployed service returned a Google error page for
`/healthz` on both `run.app` URL formats while every sibling route answered
normally, and no `/healthz` request appeared in the service log. The same view
is served at `/health`, which is not intercepted. A runbook that tells a
reader to curl `/healthz` teaches them to read a healthy service as broken.

Do not make the service public if `REQUIRE_FIREBASE_AUTH=1` and the Firebase
configuration are absent. Otherwise the service can fall back to laptop
identity mode, which was never designed for a public deployment.

## Stage 6 — real browser and real-cloud verification

Automated tests cannot replace these checks:

1. Google sign-in → type one item → click **records** → download PDF. None of
   the normal navigations may return 401.
2. Sign out and sign in again. The record must still exist in Firestore.
3. Open Chrome and Safari on real phones. Record one voice item in each and
   confirm that the recognised source text is visible and correctable.
4. Refuse microphone permission once. The text path must remain available.
5. In a fresh private window, choose **Just look around**. Seed that exact
   anonymous uid with `demo/seed_firestore.py`; the seed marks the workspace
   synthetic and makes its next reflection due. Run `mallow-reflections` from
   Cloud Scheduler. The ordinary OIDC task path should create one leaf. No
   Google sign-in, non-private window, or UI generate control is required.

   In the browser console, copy only the current anonymous uid:

   ```js
   (await window.Mallow.firebase()).auth.currentUser.uid
   ```

   Then, from the checked-out submission in Cloud Shell:

   ```bash
   export MALLOW_DEMO_UID='paste-the-anonymous-uid-here'
   export MALLOW_ALLOW_FIRESTORE_SEED=1
   python3 demo/seed_firestore.py --uid "$MALLOW_DEMO_UID"
   gcloud scheduler jobs run mallow-reflections --location "$REGION"
   ```

   The seed writes a real `users/{uid}` workspace manifest in the same atomic
   batch as the synthetic records. Firestore permits subcollections below a
   non-existent parent, but such a parent is absent from collection queries;
   without the manifest the global Scheduler cannot discover that workspace.
6. Copy a real Firebase user token from DevTools:

   ```js
   await (await window.Mallow.firebase()).auth.currentUser.getIdToken()
   ```

   Send it to `/tasks/reflections`; it must receive 403 because a user's
   token is not the Scheduler's token.

Still unproven until this stage passes: browser audio transport to Gemini,
Firestore transactions and retry behavior against the real service, and
Scheduler OIDC.

## Troubleshooting principles

- A model failure offers the text path. It never silently invokes the fake model.
- Raw audio is processed in memory and is not persisted by Mallow.
- Chrome normally records WebM and Safari MP4. Do not add an encoder before a
  real device returns an actual MIME or transport error.
- Firestore configuration failure must not downgrade to the local file journal.

## Teardown after recording

Do this only after the demo and verification evidence are safely recorded:

```bash
gcloud scheduler jobs pause mallow-reflections --location "$REGION"
```

Cloud Run already scales to zero while idle. Pausing the Scheduler is reversible.
Deleting the Cloud Run service or Firestore database is destructive and is
intentionally not part of this runbook.
